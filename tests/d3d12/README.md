# D3D12 resource and graphics parity tests

Generate the Iryven solution with `premake5 vs2026` (or `vs2022`), build
`D3D12ParityTests`, and run its executable from the Iryven repository root.
The same project is also generated by Velos's own root Premake script; run that
executable from the Velos repository root.

Run both Debug and Release. The tests require Windows Graphics Tools / the D3D12
debug layer and fail on D3D12 validation errors or corruption messages.

Coverage includes:

- DEFAULT/UPLOAD/READBACK buffers, mapped writes, GPU-only initial uploads,
  partial staged updates, CPU-visible updates, byte-for-byte copies, CBV
  alignment, raw storage views, and invalid requests.
- Multi-use texture descriptors, mip/layer ranges, cube arrays, compatible
  sRGB views, sampled depth/stencil views, filtering/addressing/anisotropic
  samplers, and invalid ranges/formats.
- Full 16x16 image comparisons for MRT output, additive blending, texture
  sampling, normalized vertex attributes, U16 indexed drawing with offsets,
  binding before the pipeline, and pipeline stride changes.
- Pipeline creation for all exposed topologies, depth-only rendering, descriptor
  root layouts, persisted PSO cache reload/corruption recovery, and backbuffer drawing/presentation.
- Depth-only drawing followed by equal-depth color drawing and full image comparison.
- RGBA8 sRGB buffer-to-image upload with exact pixel readback and invalid-region checks.

The deliberately corrupted-cache case allows validation diagnostics from the
rejected cache blob, then verifies that uncached creation succeeds and repairs it.

Descriptor tests use the RHI pool, layout, allocation, update, and binding APIs.
They cover uniform ranges, raw/structured storage buffers, sampled and writable
textures, partial/variable arrays, update-after-bind, pool destruction while work
is recorded or in flight, and independent graphics/compute push constants.

Implementation notes:

- GPU-only initial uploads currently wait for the graphics queue; command-list
  updates retain their staging resources until that frame's fence completes.
- Buffer-to-image upload currently supports 2D RGBA8/BGRA8 color images, mip
  regions and array layers. Source row pitches must be multiples of 256 bytes,
  and source offsets (including each layer) must be multiples of 512 bytes.
  Use `bufferRowLength` in pixels to describe padded source rows. Transition the
  destination to TransferDst before copying, then to the required shader layout.
- UPLOAD memory stays GENERIC_READ and READBACK memory stays COPY_DEST. When
  CPU-visible usage requires UAV writes, copy destinations, or other operations
  forbidden on those heaps, a DEFAULT buffer has a synchronized host mirror.
  Mapping refreshes it from GPU data; unmapping CPU-to-GPU mirrors uploads writes.
  Persistently mapped mirrors are synchronized around submissions too. These
  compatibility operations currently wait for the graphics queue; they prioritize
  correct memory-hint behavior over transfer throughput.
- HLSL vertex attributes use the existing `SHADER_INPUT<n>` convention. The RHI
  `semanticIndex` identifies `<n>`; Vulkan continues to use `location`.
- Root layouts map set to register space and binding to register number, with
  separate resource/sampler tables. Combined image/sampler bindings use matching
  `tN` and `sN` registers. Array register ranges must not overlap. Native DXIL
  reflection supplies resource types, array sizes, shapes, and structured strides.
  Texture declarations must match the native view shape. Storage access at one
  binding must consistently use SRV or UAV declarations across shader stages.
- Variable-count bindings must be last. Runtime shader arrays require an explicit
  layout override with a maximum count; pool budgets consume the allocated count.
  Partially bound slots and unused array tails receive null descriptors.
- Normal bindings capture values when bound. Update-after-bind bindings capture
  their latest values at submission; submitted descriptors remain immutable until
  the frame fence completes. Each snapshot retains its referenced resources.
- HLSL push constants use a cbuffer at `register(b0, space2147483647)`.
  Upload-backed root CBVs preserve partial writes and separate values per stage.
  Direct compute pipelines, descriptor binding, and dispatch are covered too.
- PSO blobs live under `<pipelineCachePath>.d3d12`. Keys include shader binaries,
  serialized roots, input/state/attachment descriptions, adapter identity and
  available driver identity. Rejected blobs retry without a cache. Cache I/O
  failures do not prevent pipeline creation.
- Shared shader-language portability, per-subresource barriers, indirect compute,
  asynchronous compute queues, mesh pipelines and queue pooling remain outside
  these tests.
